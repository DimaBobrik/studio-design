# Directions index (33)

Visual specimens: directions/_specimens/ (open index.html; montage _montage.jpg)

Each direction file is self-contained: front matter (axes, fits, subjects, neighbours), a complete `tokens.css` implementing the token contract (fonts with Hebrew fallback in the same stack), and rules. Load `_index.md` first, shortlist (the subject columns below are enough for scoring), then load only the 3 shortlisted files.

Colour rules for every direction and palette drop (audited 2026-09, script-checked oklch → sRGB, WCAG 2 contrast):
- `ink/canvas`, `ink-2/canvas`, `muted/canvas`, `muted/surface`, `ink/surface`, `accent-ink/accent` are all ≥ 4.5:1; `--c-muted` is used for small text, so it must pass 4.5 too. Exceptions are written next to the tokens (field directions whose placards/windows carry a local `[data-surface]` ink).
- Every palette drop ships a complete `Override:` line with all 10 contract colour tokens plus its measured contrast (`AA:` line). Paste the override into `assets/tokens.css` below the direction's `:root` block; never apply only canvas/ink/accent. When `accent/canvas` < 3 the accent is a fill colour only (never text, never a 1px UI line on canvas).
- If you hand-mix a custom palette (brief names colours): keep hue/chroma, move only L until the six pairs above pass, and write the ratios in DESIGN.md.
- `--fs-base` ≥ 15px (mono/UI-dense directions) or ≥ 16px (prose); labels ≥ 12px. `radius_system: 0` ⇒ `--r-pill: 0px`.

Imagery-only colours: `--img-*` tokens (glaze, clay shadow, illustration inks, shader stops) may be declared in `tokens.css` outside the palette; they are used only inside renders/illustrations/shaders, never for text, UI or text backgrounds (antipatterns #65).
SVG drawings in RTL: `direction="ltr"` on the `<svg>`, explicit `text-anchor` (runtime/README.md §8).

Fonts: Google Fonts `<link>`s are fine. Directions using Fontshare also list a `fallback:` Google face in front matter and in the token stack. Fontshare families (Clash Grotesk, General Sans, Cabinet Grotesk, Switzer, Satoshi, …) must be self-hosted for production and QA: download woff2 into `fonts/`, `@font-face` at the top of `assets/tokens.css`, drop the `api.fontshare.com` link (its CSS intermittently fails CORS in headless browsers; see `runtime/README.md` §10). Fontshare fonts are free for commercial use under the ITF Free Font License; check each family's license page before shipping.

Axis vocabulary
- **paper_band**: `light` (canvas L > 85%), `mid` (60–85%), `dark` (L < 30%), `field` (saturated full-page colour canvas).
- **display family** (coarse, used for distance): `serif` = classical-serif, high-contrast-serif, hairline-didone, didone+script, old-style-serif, chunky-serif, soft-serif-70s, slab, fat-face-serif · `grotesk` = grotesk-heavy/bold/medium/regular/light/thin/giant/quirky, neo-grotesk, wide-grotesk, wide-geometric, geometric-caps, extended-heavy · `condensed` = condensed-caps, ultra-condensed, display-heavy, crushed-display, grotesk-caps-heavy · `special` = mono+condensed, pixel, handwritten.
- **accent_hue band**: warm (10–60°), yellow (60–110°), green (110–170°), cool (200–300°), magenta/pink (300–360°), neutral (no chromatic accent), multi (a fixed set).
- **radius_system**: 0 · sharp (2–4px) · soft (8–32px) · pill · organic/arch (non-uniform).
- **D-V-M** = density, variance, motion budget (0–10).

## Hebrew display axis (Hebrew-first sites)

On a Hebrew site the Latin display face is mostly invisible: distance must be measured on the Hebrew face that actually renders (`verify.mjs` `fonts-rendered` reports it). Heebo, Assistant, Noto Sans Hebrew, IBM Plex Sans Hebrew and Miriam Libre are near-identical neutral sans at display sizes; three of them in a trio are one design.

Classes: `sans-neutral` (Heebo, Assistant, Noto Sans Hebrew, IBM Plex Sans Hebrew, Miriam Libre) · `sans-round` (Rubik, Fredoka, Varela Round) · `sans-condensed` (Noto Sans Hebrew wdth <80) · `serif` (Frank Ruhl Libre, David Libre, Noto Serif Hebrew, Bona Nova, Bellefair) · `display-heavy` (Suez One, Secular One) · `display-condensed` (Karantina) · `display-pixel` (Rubik Pixels) · `hand` (Playpen Sans Hebrew, Amatic SC, Gveret Levin). Free Hebrew pool verified 2026-10 via the Google Fonts CSS API (`/* hebrew */` subset): the faces above + Open Sans (wdth 75-100), M PLUS 1p, Arimo, Tinos, Cousine, Alef, Noto Rashi Hebrew, Solitreo and 27 Rubik display variants; Inter, Montserrat, Poppins, Ubuntu ship no Hebrew.

**Israeli evidence (2026-10, `../references/israel.md`):** 49% of 122 Hebrew pages set the display in a neutral Google sans at ≤72px (the local template); 6 of 7 Hebrew tier-A sites use a commercial/custom display face at 64-200px (Hebrew A median 88px). No Hebrew page in the scan uses a Hebrew serif display. When a brief names a commercial Hebrew face (Almoni, Ploni, Simpler, Kedem, Polin, Narkiss…) and no licence is supplied, use the substitute table in `israel.md` §2b and measure distance on the substitute's class. Two A-tier Hebrew voices to aim for: heavy statement (sans-neutral at 800-900, ≥88px, lh 0.82-1.0, 0 to -0.02em) or light large (200-400 at ≥80px).

**Rule:** a Hebrew trio differs in Hebrew display class across all three picks; if two picks must share a class, those two differ in paper band AND accent band, and one of them takes its swap below (log the swap as a knob). Only use weights the Hebrew face ships (single-weight faces: Suez One, Secular One, Bellefair, Rubik Pixels, Varela Round, Gveret Levin = 400 only).

**Families on Hebrew pages (≤3 + declared outlier/mono).** Every direction's tokens end with a `:root:where([lang="he"])` block that puts the Hebrew display and Hebrew body faces first in `--f-display` / `--f-body` (all listed Hebrew faces ship Latin), so a Hebrew page renders 2 families (+ mono/outlier), not Latin display + Latin body + two Hebrew faces. Knob `latin-display`: keep the Latin display face for Latin words (then it is the 3rd family). Script/ornament faces (Pinyon Script etc.) are Latin-only outliers, never on Hebrew words.

**Swaps are also knobs.** A listed swap face may be used even without a collision (e.g. to make a repeat of the same direction feel new, or because the brief's tone suits it): log it as a knob (`knobs.he_display=<face>`) and use the swap face's class for distance. Only swap within the direction's own table row.

## Selection algorithm (shortlist 3 maximally distant directions)

Inputs: brief (subject, audience, site type, tone words, explicit colours/fonts/references), project log (last runs), seed.

1. **Hard filter by site type.** Keep directions whose `fits` contains the requested type (ecommerce / landing / company). Full page sets: use the type of the main deliverable.
2. **Brief-word override.** If the brief names a colour, font, reference site, or a look ("newspaper", "retro", "minimal Japanese"), keep directions that honour it (or route to a custom palette inside the closest direction); explicit words beat every rule below, including guards and bans.
   - **Brief-fixed palette** (the client's colours are given and not negotiable, e.g. an existing brand): map them to token roles first: the lightest/darkest neutral → canvas/ink, a mid neutral → surface/muted (check `muted/canvas` ≥ 4.5), the brand colour → accent only if `accent-ink/accent` ≥ 4.5, otherwise it becomes a fill/ornament colour (gold, champagne, pastel on light canvas → fills, rules, icons ≥ 3:1, never text) and a darker derivative carries text links. Every direction then uses this palette instead of its own; paper band and accent no longer separate the trio, so **distance is measured on** display class, Hebrew display class (Hebrew sites), layout/hero archetype (`hero_object` + hero id), radius system and motion budget (≥2 of these 5 must differ between any two picks). Write the mapping + ratios in DESIGN.md.
   - **Prior stated preference**: if the user already chose, liked or asked for a direction (in this or an earlier, even unlogged, session: "I liked the dark control-room one"), it goes into the trio as a brief override, may bypass the `fits` filter with a one-line stated adaptation ("cold-chrome-luxury adapted to a store: product cards on light plates"), and is excluded from penalties; the other two picks are chosen for distance from it.
3. **Subject affinity score** (0–3 per direction): +2 if the subject (industry, materials, artefacts) appears in `subjects_good` or is a close sibling; +1 if the audience/tone words match the essence (e.g. "calm", "trust" → density ≤5 & motion ≤4); −3 (reject) if it appears in `subjects_bad`. Drop score ≤0. Guarded directions need +2 AND the guard condition.
4. **Recency rotation (two logs).** Read (a) the project log `.studio-design/log.json` and (b) the user-global log `~/.studio-design/global-log.json` (last 20 runs across all projects; `scripts/log-run.mjs` creates it; if the home folder is not writable, skip it silently). Project identity = the `project` slug (the same slug in another folder or a re-run of the same brief is the same project; `scope: "brief"` marks a brief re-run without a project folder). Entry: `{date, project, scope, site_type, n, seed, shown:[a,b,c], chosen, drop, knobs, paper, display, he_display, accent, hero_object, hero, nav, footer}`.
   - **Exclude** any slug CHOSEN in the last 3 entries of this project (both logs).
   - **Penalise −2** any slug SHOWN (in `shown`) in the last 2 entries of this project/brief; **−1** any slug chosen in the last 3 global entries (other projects). Penalties re-rank; they do not drop a direction below the survivor list (use the relax order below if the trio runs out).
   - Prefer directions whose (paper, display family) pair is absent from the last 5 global runs.
   - **Hero device rotation:** `hero_object` ∈ `lathe-render | device-render | drawing | photo | video | type-only | media-collage | data-viz | illustration`. The new run's hero must not use the same `hero_object` as the last CHOSEN run of the same project (entries with `chosen` set; shown-only or aborted runs don't count). State the new one in the trio lines.
   - If a slug must repeat (single fit), change its palette drop and ≥2 knobs, and record the deltas.
5. **Distance picking.** From the survivors, build the trio greedily:
   - Pick #1 = highest (affinity + penalties) score; ties → seeded order (step 6).
   - Pick #2 = highest-scoring direction that differs from #1 on **≥2 of {paper_band, display family, accent band}** (Hebrew sites: Hebrew display class counts as the display axis) and is not in #1's `neighbours`.
   - Pick #3 = highest-scoring direction that differs from BOTH #1 and #2 on ≥2 of the three axes and is not a neighbour of either. Prefer one that also differs in motion budget by ≥3 from at least one pick.
   - If no candidate satisfies ≥2 axes, relax to ≥1 axis + different radius_system, and say so.
6. **Seeded choice (exact).** `seed = FNV-1a 32-bit("<project>|<site_type>|<N>")`, N = number of prior global-log entries for that project (project log if the global log is unavailable); get it with `node scripts/log-run.mjs seed --project <slug> --site-type <type>` (JS in `scripts/new-project.md`). Ties among k equal candidates: sort them alphabetically by slug, rotate the list left by `seed mod k`, take the first. The seed never overrides filters or penalties. Print the seed and N.
7. **Present the trio** in one line each: slug · why it fits the subject (one concrete link to the subject's world) · what the page would be remembered by (its signature move) · hero_object · differs-from-last line ("last shown: x, y, z; last chosen: w; this differs on paper + display").
8. **Log immediately, every run.** Right after the trio is shown (process step 2, before any concept is built, also for concept-only or aborted runs) append the entry to BOTH logs: `node scripts/log-run.mjs shown --project <slug> --site-type <type> --shown a,b,c --set hero_object=<…>`. After the user (or the "just do it" default) picks, fill it: `node scripts/log-run.mjs chosen --project <slug> --chosen <slug> --set drop=B paper=light display=grotesk he_display=serif accent=warm hero=H-24 nav=N15 footer=FT-01 knobs.hero_scale=giant`. Then choose a palette drop (not the one used last time for this slug) and set 2–3 knobs (swap faces from the Hebrew table count as knobs).

**Never fail to produce a trio.** When filters leave fewer than 3 candidates (typical for trust briefs: law, clinics, accounting, finance, public sector, where only a few light sans directions score >0), relax in this order and say which step was used:
1. Add score-0 directions whose essence can carry trust with a stated adaptation: `swiss-signal-grid` (civic signage: accessibility, law, public services), `broadsheet-duet` (publications, legal commentary, firms with real articles), `estate-didone` (private clinics, notaries, family offices: navy/bottle-green drop), `forest-bone-heritage` (regional/family firms), `film-title-bands` (Polar drop: industrial/engineering B2B), `telemetry-terminal` (prose mode: compliance, cyber, data-protection law), `atmospheric-sky` (insurance, health systems). Write the adaptation in one line ("swiss-signal-grid with the Signal red drop swapped for ultramarine, prose mode 17px, no caps labels").
2. Allow a guarded direction (`broadsheet-duet`, `media-bento-night`, `dev-playground`) inside its guard rules.
3. Relax the distance rule to ≥1 axis + different radius_system (or, for Hebrew sites, a different Hebrew display class).
4. Allow a neighbour pair, but then the two must differ in paper band and palette drop.
5. Last resort: one direction in two palette drops + a knob set as the second/third option, labelled as variants, not directions.
