Sections catalog is split in three files: `sections-hero-nav.md` (§0 composition rules, §1 hero, §2 nav), `sections-content.md` (§3 features … §7 CTA, §9 gallery, §10 team/about/contact, §11 stats/newsletter, §13 case study), `sections-footer-wp.md` (§8 footer, §12 WordPress mapping). E-commerce patterns: `ecommerce-plp-pdp.md` / `ecommerce-cart-account.md`; widgets: `widgets.md`; backgrounds: `backgrounds.md`.

**Quick index**

- §2. Navigation / header (Hallmark archetypes + effect ids): N1a…N17, NV-FS…NV-DK (22)

Load after the macrostructure and direction are chosen. Each section = one ACF Flexible Content layout = one self-contained `<section>` with `data-fx` params that map 1:1 to ACF fields. 

Row format: `id | name | wireframe | use when | module / recipe | knobs (3, Hallmark style) | ACF sketch`.
Wireframe notation: family name first (`split[…]`, see §0.2), `[ ]` block, `|` column split, `/` stacked, `~` moving, `^` sticky/pinned, `<>` horizontal travel, `IMG` `VID` `H1` `CTA` `txt`.

## 0. Page composition rules (mechanical, check every page)

1. **No two sections of the same archetype on one page** (id prefix + number). Same archetype on a *different* page of the site must change >= 1 knob; record deltas in the plan.
2. **Layout families** (tag every section with one; family names are lowercase words so they never collide with section id prefixes like `T-` team, `S-` proof, `G-` gallery, `Q-` FAQ, `H-` hero): `text` text-led, `split` 2-col, `grid` uniform grid, `bento` bento/irregular grid, `stack` stack/sticky/pinned, `track` horizontal travel, `list` list/index/table, `media` full-bleed media, `loop` marquee/loop, `rail` carousel/rail, `disclosure` accordion/tabs. Wireframes start with the family name: `split[IMG | txt]`, `^track[…]`. A page of n sections uses **>= ceil(n/2) families**; no family more than twice in a row.
3. **Zigzag cap:** <= 2 consecutive `split` sections, and never image-left/text-left alternation more than 2 times.
4. **Marquee cap:** <= 1 `loop` section per page (announcement bar in ecommerce header is exempt only if no other marquee on the page).
5. **One signature scroll moment per page** (pin/scrub/horizontal/sphere). Mark it `SIG` in the plan. Other sections use at most a single reveal primitive.
6. **Eyebrows <= ceil(n/3)**, never in consecutive sections, only for ordinal/real categories. No `01 / FEATURES` decoration.
7. **Section headline <= 8 words, sub <= 25 words**, one asset/CTA. > 5 items -> switch component (tabs, grouped 2-col, rail, accordion).
8. **CTA intent is unique**: one label per intent across nav/hero/sections/footer (e.g. "Book a call" everywhere, not also "Get in touch" and "Contact us"). Labels <= 3 words, never wrap.
9. **Background variety**: vary section padding (`--section-y` top, `calc(var(--section-y)*.7)` bottom is fine) and background mode, but keep one Page Theme (see backgrounds.md dark-to-light sheet exception).
10. **Kill the shared tail**: pricing, proof and footer shapes rotate between projects too; do not end every page with S-05 -> P-01 -> CTA-02 -> FT-04.

**Hero rules**
- Height `min-height: clamp(60vh, 75dvh, 88dvh)`; never `100vh`; full-viewport only for `media`-family cinematic heroes (H-02, H-10, H-15, H-18), which still use `100dvh` not `100vh`.
- **Eyebrow + H1 + lede + CTA fit at 1280x800** above the fold (and 390x844 on mobile without the lede being cut mid-sentence).
- H1 <= 2 lines desktop for statements, <= 3 lines max; <= 7 words / <= 50 chars when self-written; Hebrew headlines run ~15% shorter in chars, keep the same line cap.
- Max 4 text elements (eyebrow OR brand strip, H1, lede <= 20 words, CTA 1 + optional 1). No trust strip, pricing teaser or badge pill inside the hero; logo wall goes directly under it.
- `padding-block-end >= 1.3 x padding-block-start`; <= 2 centred elements; centred hero banned when variance dial > 4.
- LCP element: H1 text or first image with `fetchpriority="high"`; never lazy; SplitText hero reveal must start <= 100 ms after fonts load and finish <= 1.2 s.
- One polish device max: marquee-overflow H1 bleeding past edge, scoped cursor spotlight, meaningful oversized numeral, or inline image in type.
